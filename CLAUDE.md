## What this repo is

`akka-platform-api` is a Java client library for the Akka Platform APIs, published for use by external consumers. It contains API schemas and the generated Java client code derived from them. There are two planes:

- **Control Plane** (`schemas/control-plane/openapi/`): A Kubernetes-based REST API. The OpenAPI schema (`api.json`) is fetched from a live Kubernetes cluster and transformed via a custom SBT plugin.
- **Federation Plane** (`schemas/federation-plane/protobuf/`): A gRPC-based API covering auth, billing, data management, organizations, projects, and users, defined as protobuf schemas.

## Build commands

```bash
sbt compile              # compile everything (including java-client code generation)
sbt java-client/compile  # compile just the java-client subproject
```

The root project has no source files — it only hosts the `ControlPlaneApis` SBT plugin that manages the schema fetch/transform task.

## Regenerating the control-plane OpenAPI schema

The file `schemas/control-plane/openapi/api.json` is committed to the repo. To regenerate it from a live cluster:

```bash
sbt controlPlaneApiSchema
```

This requires `kubectl` access. By default it uses the current kubectl context. Set `KUBECTL_CONTEXT` env var to target a specific context. The task fetches raw OpenAPI specs from the `kalix.io/v1alpha1` and `kalix.io/v1beta1` API groups and runs them through the `ControlPlaneApis` SBT plugin transformation pipeline.

## Architecture

### SBT subprojects

- **root** (`.`): Enables `ControlPlaneApis` plugin. No source code — only schema management.
- **java-client** (`java-client/`): Generates Java source from two schema sources:
  1. OpenAPI schema → Java REST client (via `sbt-openapi-generator`, `java/native` library, async)
  2. Protobuf schemas → Java gRPC client stubs (via `sbt-akka-grpc`, client-only)

### The `ControlPlaneApis` plugin (`project/ControlPlaneApis.scala`)

The main logic for transforming raw Kubernetes OpenAPI into the committed `api.json`. Key transformations applied:

1. **Path filtering** — keeps only namespaced, non-sub-resource paths (drops status/scale, watch, non-namespaced resources)
2. **Parameter renaming** — `{namespace}` → `{projectId}` throughout paths and schemas; removes Kubernetes-only query params (dryRun, fieldManager, watch, etc.)
3. **Operation ID normalization** — renames Kubernetes-style IDs (e.g., `listNamespacedKalixService`) to clean ones (`listServices`)
4. **Component name normalization** — strips package prefixes and "Kalix" from schema component names; merges duplicates by longest common CamelCase suffix; configured manual renames in `controlPlaneApiRenameSchema`
5. **Inline object extraction** — promotes inline nested object schemas to top-level named components

### Generated code

All generated Java source lives under `java-client/target/open-id-generator/src/main/java/`. The packages are:
- `io.akka.platformapi.controlplane` — invoker/client base
- `io.akka.platformapi.controlplane.api` — API interface classes
- `io.akka.platformapi.controlplane.model` — model POJOs

gRPC stubs are generated by akka-grpc from `schemas/federation-plane/protobuf/kalix/`.

### Java client library (`java-client/src/main/java/io/akka/platformapi/`)

The hand-written SDK layer that wraps the generated code and provides the public API of the library.

- **`AkkaPlatformSdk`** — main entry point. Constructs and owns the gRPC channels and HTTP client, wires authentication, and exposes typed accessors for each service (`auth()`, `projects()`, `organizations()`, `users()`, `controlPlaneApi()`). Also provides `resolveProjectId()` to look up a project UUID by its friendly name.
- **`AkkaPlatformSdkConfig`** — immutable configuration (API host + token config). `loadDefault()` auto-detects credentials from env vars (`AKKA_OAUTH_TOKEN`, `AKKA_OAUTH_TOKEN_FILE`, or `AKKA_TOKEN`) then falls back to the `akka` CLI. Named factory methods (`withRefreshToken`, `withOAuthToken`, `withOAuthTokenFile`) are available for explicit configuration.
- **`TokenConfig`** — marker interface for credential configuration. Two built-in implementations: `RefreshTokenConfig` (holds a long-lived refresh token) and `OAuthTokenConfig` (holds either a fixed subject token or a file path from which it is re-read on every exchange, plus the required audience). Custom auth can be provided by implementing both `TokenConfig` and `TokenFetcher` on the same class.
- **`TokenFetcher`** — interface with a single `getToken()` method returning `CompletableFuture<TokenWithExpiry>`. `TokenWithExpiry` (a record nested inside `TokenFetcher`) pairs the bearer token string with its expiry `Instant`. Built-in implementations are `RefreshTokenFetcher` and `OAuthTokenFetcher` (both package-private, constructed by `AkkaPlatformSdk` from the `unauthedAuthClient`).
- **`AccessTokenCache`** — package-private, thread-safe cache for the short-lived access token. Delegates to a `TokenFetcher` when the cached token is absent or within 60 seconds of expiry. Shared by both the gRPC `CallCredentials` and `ControlPlaneHttpClient`.
- **`ControlPlaneHttpClient`** — package-private `HttpClient` wrapper that intercepts every REST call, extracts the project UUID from the URI path, resolves the target regional endpoint (caching region lists per project in `AkkaPlatformSdk`), and injects the `Authorization: Bearer` header from `AccessTokenCache`.

## Key configuration points

- `controlPlaneApiExcludeResourceVersions` — resource versions to omit entirely from the schema
- `controlPlaneApiRenameSchema` — manual overrides for component names that the auto-deduplication gets wrong
- `controlPlaneApiVersionGroups` — which API group/version pairs to fetch from the cluster
